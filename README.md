# MedVision AI — Academic Medical Imaging Workspace

A React + FastAPI academic prototype for exploring a medical-imaging workflow. The interface includes a dashboard, scan upload/preview, analysis history, analytics overview, report centre, model registry and an explainability panel.

> **Clinical safety:** This project is not a medical device and must not be used for diagnosis, triage or treatment decisions. The current starter validates uploaded images only. It does not contain trained weights or perform disease classification. It does not generate a real Grad-CAM heatmap.

## Current interface

- Light medical-workstation design: white surfaces, deep navy navigation, cyan/teal accents and responsive layout.
- Sidebar: Home, New Analysis, Analysis History, Analytics, Reports, Model Information and Settings.
- Chest X-ray and Brain MRI workflows; CT and Ultrasound are labelled Coming Soon.
- Image preview and basic file validation (JPG/PNG/WEBP, maximum 15 MB).
- Analysis response is explicitly labelled demo-only; no invented prediction or confidence score is displayed.
- Browser-local analysis history.
- Downloadable PDF demo report, clearly stating that no model prediction was performed.
- Grad-CAM panel reserved for a genuine explanation generated by a compatible trained CNN.

## Project structure

```text
MedVisionAI/
├── frontend/                 # React + Vite interface
├── backend/                  # FastAPI API and PDF report service
├── ml/                       # Task-specific model training/evaluation placeholders
├── dataSet/                  # Add approved datasets here; do not commit private patient data
├── reports/                  # Report templates and generated reports
└── docs/                     # Architecture and research notes
```

## Requirements

- Python 3.12 recommended
- Node.js 20 or newer
- npm

## Run the backend (Windows PowerShell)

```powershell
cd MedVisionAI\backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Backend: http://127.0.0.1:8000  
API documentation: http://127.0.0.1:8000/docs  
Health check: http://127.0.0.1:8000/health

## Run the frontend (second terminal)

```powershell
cd MedVisionAI\frontend
npm install
npm run dev
```

Open the Vite URL shown in the terminal, normally http://localhost:5173/.

## API endpoints

- `GET /` — API status
- `GET /health` — health check
- `POST /api/analyze` — validates an uploaded image and returns a demo-only response
- `POST /api/reports/demo` — generates a PDF that clearly identifies the output as a demonstration

## What remains before real AI analysis

1. Select and document suitable, legally usable datasets for each modality/task.
2. Define labels and patient-level train/validation/test splits to avoid patient leakage.
3. Train a separate model for each supported task; store versioned weights outside source control where appropriate.
4. Implement preprocessing consistently between training and inference.
5. Evaluate on a held-out patient-level test set and report sensitivity, specificity, precision, recall, F1 and AUROC. Do not claim clinical performance from training accuracy.
6. Implement Grad-CAM for a compatible CNN architecture and display it alongside the original image with an explanation that it is an attribution visualization, not proof of a lesion.
7. Only then enable model-backed predictions and include model version, limitations and measured metrics in reports.

For the brain-stroke research task, use appropriate MRI sequences and a dataset designed for that task; a generic brain MRI classifier must not be presented as a stroke diagnostic system.
